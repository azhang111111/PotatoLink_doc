# 17 客户账号与跨设备订单查询

## 目标与现状

客户可在不同设备登录后查看本人询价、报价和全部订单。游客仍可浏览公开品种、供应和溯源资料。现有单笔限时安全链接继续有效，用于分享和旧交易认领，但首页的本地“最近订单”记录不能充当客户身份。

当前每次询价都会创建一条 `crm_customer` 联系人记录，订单通过 `trade_order.customer_id` 关联该记录。相同手机号、邮箱、姓名或企业名称均不能证明这些记录属于同一账号，禁止按文本相同自动合并历史交易。

## 身份与登录

1. 客户账号使用独立的随机内部 ID，与 `crm_customer` 联系人、内部员工账号和企业主体分开。一个账号可绑定多个经过验证的联系方式；手机号使用带国家区号的规范格式，邮箱使用一致的规范化规则。
2. 中国客户首先支持手机号验证码；俄语 H5 同时提供邮箱验证入口。两种方式均可注册或登录同一个客户账号，但新增或更换联系方式必须在已登录状态下再次验证，不能仅凭相同企业名称合并账号。微信身份后续作为同一账号的另一种绑定方式。
3. 浏览公开资料不要求登录。客户提交新询价前完成登录，后续询价、报价和订单通过服务端账号归属查询；销售代客户录入的交易需要客户主动认领或经受控人工核验后绑定。
4. 登录使用短期访问会话和可轮换的续期会话。退出、账号停用或异常事件可撤销会话。客户端不得把验证码、会话令牌或完整订单信息写入日志。
5. 验证码通过阿里云短信或邮件通道发送。验证码一次有效、短时过期，并按联系方式和来源限制请求及验证次数；无论联系方式是否存在，对外返回相同的发送结果，避免枚举账号。阿里云密钥只通过部署配置注入。

登录验证码是客户账号正式启用的前置能力；订单状态提醒、营销和其他业务通知仍可暂缓，不随登录功能自动开启。没有可用的真实验证通道时，不在公开环境启用客户账号入口。开发环境的验证码替身必须只在显式测试配置下工作。

## 交易归属与旧订单认领

- 新询价在已登录会话中创建时，服务端同时保存账号与该询价的客户联系人记录的关联；报价和订单沿既有询价关系继承归属。
- 旧订单认领要求客户先登录，再提交原订单的有效安全链接。服务端校验令牌哈希、有效期、撤销状态与订单号绑定后，在同一事务中建立账号与原 `customer_id` 的关联。一个客户联系人记录已归属其他账号时拒绝认领并转人工复核。
- 只有手机号或邮箱相同而没有有效链接时，不自动开放历史订单。链接遗失或过期时，由销售核实后重新签发单笔链接；人工迁移需保留操作者、原因和审计记录。
- 一个账号可有多笔询价和订单。第一版不把整个企业的交易自动开放给所有联系人；企业多成员协作与授权另行设计。

## API 与页面切片

1. `POST /auth/customer/challenges`：请求手机或邮箱验证码；对外响应不泄露账号是否存在。
2. `POST /auth/customer/sessions`：校验验证码并创建或登录客户账号，返回客户会话。
3. `POST /auth/customer/sessions/refresh`、`DELETE /auth/customer/sessions/current`：轮换与退出。
4. `GET /customer/me`、`GET /customer/inquiries`、`GET /customer/orders`、`GET /customer/orders/{orderNo}`：只按已验证账号的服务端归属查询；订单号不能代替鉴权。
5. `POST /customer/order-claims`：使用已有订单号与安全链接令牌认领旧订单；请求和审计中不得记录令牌明文。
6. 客户端增加登录页和“我的订单”列表。登录后跨设备读取服务端列表；未登录时可保留明确标注为“本机最近订单”的安全链接入口，避免误称“我的全部订单”。

接口详细 schema 和错误码在实现时写入 `api/openapi-v1.yaml`，数据库使用新的 Flyway 迁移建立账号、已验证联系方式、会话、交易归属和审计结构，不修改既有迁移。服务端同时校验账号归属与数据范围，不依赖前端过滤。

## 交付与验收

按账号与归属数据模型 → 阿里云验证码通道 → 客户会话 → 新询价自动归属 → 旧订单认领 → “我的订单”页面的顺序交付。上线前至少验证：同账号换设备仍看到订单；不同账号不能凭订单号或相同联系人字段读取订单；旧链接被撤销或过期后不能认领；已认领订单不被第二个账号抢占；验证码限流和会话撤销生效；阿里云发送失败时不创建已验证身份。
