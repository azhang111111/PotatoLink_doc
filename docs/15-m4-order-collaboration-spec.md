# 15 M4 订单协同规格

## 1. 目标与范围

M4 将已接受报价转化为可执行订单，并把供应批次、库存占用和客户可见履约节点连接起来。第一阶段包含：

- 客户接受有效报价后，原子创建唯一的待锁定订单。
- 销售或运营为每条订单明细选择真实供应批次，并原子建立临时锁定。
- 合同或定金确认后，将临时锁定转为正式占用。
- 内部人员维护履约节点，客户通过限时安全链接查看订单和公开节点。
- 取消、超时和释放库存均保留流水、原因和操作审计。

本阶段不包含在线支付、电子签约、自动运费计算、第三方物流接口和一个明细拆分多个批次。

## 2. 已确认的第一版边界

1. 客户接受报价时创建 `PENDING_LOCK` 订单，但不立即修改库存。
2. 商品薯订单类型固定为 `COMMODITY_STANDARD`；种薯接受报价时明确选择 `SEED_TRIAL` 或 `SEED_STANDARD`。
3. 一个订单可以包含多个品种，但每条明细只能选择一个同业务类型、同品种的供应批次，且不得混装品种。
4. 销售默认应在接受报价后的 2 个工作小时内完成批次确认。
5. 临时锁定默认有效 24 小时；合同或定金确认后转为正式占用。
6. 第一版每条订单明细同时只允许一个活动批次分配。释放或过期后旧分配保留为历史，可以重新选择批次；后续如需同时拆分多个批次，通过新迁移放开活动分配唯一约束并扩展界面，不修改历史迁移。
7. 客户只看到订单快照和标记为客户可见的履约节点，不显示内部库存、成本、审核备注或操作账号。

## 3. 报价接受与订单创建

接受动作必须在一个数据库事务内完成：

1. 校验安全令牌、报价版本归属、当前版本、`SENT` 状态和有效期。
2. 校验 `Idempotency-Key`；相同键和相同请求返回原结果，不同请求返回冲突。
3. 校验订单类型和起订量。商品薯正式订单默认总量不少于 20 吨且单品种不少于 5 吨；种薯试种订单不少于 1 吨；种薯正式订单总量不少于 5 吨且单品种不少于 1 吨。批次级规则在锁定时再次校验。
4. 将报价版本和报价主体更新为 `ACCEPTED`，询价更新为 `WON`。
5. 从报价版本复制订单、明细、价格、规格、包装、交付约定、负责人和客户快照，创建唯一的 `PENDING_LOCK` 订单。
6. 写入 `ORDER_CREATED` 事件、操作审计和可靠事件；通知失败不得回滚订单事务。

一个报价版本最多生成一个订单。重复接受不得创建第二个订单。

## 4. 订单状态机

```text
PENDING_LOCK
  → TEMP_LOCKED
  → CONFIRMED
  → FULFILLING
  → SHIPPED
  → DELIVERED
  → COMPLETED

PENDING_LOCK | TEMP_LOCKED | CONFIRMED | FULFILLING
  → SUSPENDED
  → 原暂停前状态

PENDING_LOCK | TEMP_LOCKED | CONFIRMED
  → CANCELLED
```

状态说明：

| 状态 | 含义 | 库存影响 |
|---|---|---|
| `PENDING_LOCK` | 报价已接受，等待内部选择批次 | 无 |
| `TEMP_LOCKED` | 全部明细已建立临时锁定 | 增加 `temp_locked_kg` |
| `CONFIRMED` | 合同或定金已确认 | 临时锁定转入 `committed_kg` |
| `FULFILLING` | 已开始分选、包装、检测或备货 | 保持正式占用 |
| `SHIPPED` | 已完成出库并发运 | 减少 `on_hand_kg` 和 `committed_kg`，增加 `fulfilled_kg` |
| `DELIVERED` | 客户已签收或完成约定交接 | 无新增库存影响 |
| `COMPLETED` | 业务完结 | 无新增库存影响 |
| `SUSPENDED` | 因业务、质量或合规原因暂停 | 保持当前占用，禁止继续推进 |
| `CANCELLED` | 发运前取消 | 释放所有未履约占用 |

状态只能通过明确动作接口推进，客户端不得直接提交目标状态。暂停必须记录原因；恢复时由后端恢复到审计记录中的暂停前状态。

## 5. 批次分配和库存事务

### 5.1 临时锁定

内部人员一次提交整单全部明细的批次选择。后端必须：

1. 校验每条订单明细恰好出现一次，分配数量等于订单数量。
2. 校验批次已审核、业务类型和品种与订单明细一致，且状态允许接单。
3. 按批次 ID 升序锁定 `supply_batch_inventory` 行。
4. 使用 `on_hand_kg - temp_locked_kg - committed_kg` 重新计算可售量。
5. 所有批次均充足后，创建分配和占用记录，增加 `temp_locked_kg`，写库存流水和审计。
6. 任一明细失败时整体回滚，订单保持 `PENDING_LOCK`。

### 5.2 正式占用

确认合同或定金时，在同一事务内将全部有效占用从 `TEMP_LOCKED` 转为 `COMMITTED`：

```text
temp_locked_kg -= quantity_kg
committed_kg   += quantity_kg
```

### 5.3 出库

发运时将全部正式占用转为 `FULFILLED`：

```text
on_hand_kg   -= quantity_kg
committed_kg -= quantity_kg
fulfilled_kg += quantity_kg
```

### 5.4 超时与释放

- 临时锁定到期任务只处理仍为 `TEMP_LOCKED` 的占用，并使用版本号和行锁保证只释放一次。
- 超时释放后，活动分配标记为 `RELEASED`，订单回到 `PENDING_LOCK`，允许创建新的批次分配；历史分配不覆盖、不删除。
- 人工释放和订单取消必须填写原因。
- 已履约库存流水不删除、不反向伪造；发生退货时使用独立的后续业务动作。

## 6. 权限和数据范围

| 动作 | 销售 | 销售经理 | 运营 | 质检 | 管理员 |
|---|---:|---:|---:|---:|---:|
| 查看本人订单 | 是 | 是 | 是 | 是 | 是 |
| 查看全部订单 | 否 | 是 | 是 | 按需 | 是 |
| 选择批次并临时锁定 | 本人订单 | 是 | 是 | 否 | 是 |
| 确认合同或定金 | 本人订单 | 是 | 是 | 否 | 是 |
| 新增履约节点 | 本人订单 | 是 | 是 | 质量节点 | 是 |
| 暂停、恢复或取消 | 否 | 是 | 是 | 质量暂停 | 是 |
| 生成客户安全链接 | 本人订单 | 是 | 是 | 否 | 是 |

销售的数据范围沿用询价主负责人和备用负责人。订单创建时保存负责人快照；后续转移必须单独留痕。

## 7. 客户订单视图

客户通过不可枚举、限时、可撤销的订单令牌访问，只能看到：

- 订单号、订单状态、业务类型、金额和币种。
- 品种、数量、规格、包装和交付约定快照。
- 路线和责任截止点快照。
- 标记为客户可见的履约节点及其俄文内容。
- 与订单和批次关联、且授权级别允许的文件。

完整交易文件授权必须保存关联订单 ID，并校验订单明细所分配的批次与文件所属批次一致；植物检疫证书只能向该关联订单的客户授权。

订单号和雪花 ID 均不能代替访问令牌。令牌只保存 SHA-256 哈希；访问次数和最后访问时间需要记录。

## 8. 接口交付顺序

1. 扩展接受报价接口，原子返回报价结果和新建订单。
2. 实现内部订单列表和详情。
3. 实现整单临时锁定、释放和正式确认。
4. 实现履约节点与订单状态推进。
5. 实现订单安全链接和客户订单页。
6. 实现临时锁定超时释放任务。

详细路径和请求响应以 `api/openapi-v1.yaml` 为准。

## 9. M4.1 退出条件

- 订单状态、库存副作用、权限和异常分支形成一致文档。
- OpenAPI 覆盖接受报价创建订单、订单列表/详情、锁定、释放、确认、履约节点和安全访问。
- Flyway V012 建立订单、订单明细、单批次分配、库存占用、路线快照、履约节点和订单安全访问结构。
- 原有 Flyway 迁移不被修改。
- 下一阶段可以直接按契约实现 Java 订单模块和前端订单工作台。
