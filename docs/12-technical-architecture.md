# 12 技术架构基线

本文档记录 PotatoLink 中俄薯贸第一版的已确认技术方向。代码仓库建立后，详细设计、接口定义和部署参数在代码仓库继续维护，并引用本基线版本。

## 1. 架构原则

- 采用前后端分离架构。微信小程序、俄语 H5 和管理后台不直接访问数据库，只通过后端 API 处理业务。
- API 使用 HTTPS 和 JSON，第一版统一使用 `/api/v1` 路径前缀。
- 后端采用模块化单体架构。模块在代码和数据库访问边界上保持清晰，但 MVP 不引入微服务、服务注册中心和分布式事务。
- 询价、报价、审批、库存锁定、订单和审计等关键操作由后端统一校验，不能仅依赖前端控制。
- 所有密钥通过环境变量或密钥管理服务注入，不提交到 Git。

## 2. 后端技术栈

| 类别 | 已确认方案 | 主要用途 |
|---|---|---|
| 语言 | Java 17 LTS | 后端主要开发语言 |
| 应用框架 | Spring Boot 3.5.x | Web、配置、事务和应用基础设施 |
| Web 模型 | Spring MVC | REST API，不采用响应式 WebFlux |
| 安全 | Spring Security | 微信登录、令牌认证、角色和接口授权 |
| 数据访问 | MyBatis-Plus + 显式 SQL | 常规数据维护和复杂业务查询 |
| 关系数据库 | PostgreSQL | 核心交易、客户、批次和审计数据 |
| 缓存 | Redis | 验证码、短期令牌、幂等和必要的分布式锁 |
| 数据库迁移 | Flyway | 数据库结构版本管理 |
| 接口规范 | OpenAPI | 前后端联调和接口文档 |
| 文件存储 | MinIO / 云对象存储 | 报告、证书、合同、运输附件和图片 |
| 构建 | Maven | 依赖和构建管理 |
| 测试 | JUnit 5、MockMvc、Testcontainers | 单元、接口和数据库集成测试 |
| 运行监控 | Spring Boot Actuator、Micrometer | 健康检查、指标和故障定位 |
| 部署 | Docker、Nginx | 环境一致性、HTTPS 和反向代理 |

生产环境使用的 PostgreSQL、Redis 和对象存储具体版本及云服务商，在部署资源确认后锁定。PDF 报价单、Excel 导出和定时任务所使用的具体库在技术详细设计阶段通过最小验证后确定。

所有业务表主键使用 19 位雪花 ID。后端实体使用 `Long`，数据库使用 `BIGINT`，MyBatis-Plus 初始实现使用 `ASSIGN_ID` 并通过统一 ID 生成接口封装。所有外部 API、JSON 和前端 TypeScript 类型将 ID 定义为字符串，禁止转换为 JavaScript `number`。雪花 ID 只用于数据标识，安全链接继续使用不可预测的加密随机令牌。

## 3. 后端模块边界

建议初始包结构按业务领域组织，而不是按 controller、service、mapper 做全局分层：

```text
identity        用户、微信登录、客户身份和角色权限
catalog         商品薯、种薯、品种、规格和包装
supply          供应批次、库存、可售数量和库存锁定
inquiry         询价、分配、跟进和响应 SLA
quotation       报价、版本、审批、有效期和 PDF
sample          样品申请、审核、发货和回访
order           订单、订单明细、合同归档和状态
shipment        路线、口岸、交接节点和运输附件
document        报告、证书、授权、脱敏和水印
notification    微信、邮件及发送结果
i18n            中俄内容、翻译审核和发布状态
reporting       报表、导出、成本和毛利权限
audit           关键操作、访问和导出审计
```

模块之间通过明确的应用服务或领域事件协作，禁止跨模块随意操作对方的数据表。未来只有在业务量、团队规模或独立部署要求得到验证后，才评估拆分微服务。

## 4. 前端技术栈

| 应用 | 已确认方案 | 说明 |
|---|---|---|
| 微信小程序 | uni-app、Vue 3、TypeScript | 面向微信客户和内部销售辅助操作 |
| 俄语 H5 | uni-app、Vue 3、TypeScript | 面向俄罗斯采购商的移动网页入口 |
| 管理后台 | Vue 3、TypeScript、Vite、Element Plus | 供应、询价、报价、订单、内容、权限和报表管理 |

微信小程序与俄语 H5 使用同一套 uni-app 工程，但按平台能力设置明确边界：

- 可共享领域类型、API 客户端、状态管理、校验规则、多语言资源和通用业务组件。
- 微信授权、订阅消息和小程序文件能力封装在微信平台适配层，不进入 H5 通用代码。
- H5 的游客询价、安全链接、邮箱验证和浏览器能力封装在 H5 平台适配层。
- 关键页面分别在微信开发者工具和主流移动浏览器中验收，不能只依赖统一编译通过。
- 管理后台保持独立应用，不复用面向客户的页面组件；可共享接口类型和错误码定义。

前端依赖版本在代码仓库初始化时锁定并提交 lockfile。状态管理、请求封装、国际化和测试工具的具体库在前端脚手架验证后记录，避免在需求阶段引入不必要的依赖。

## 5. 前后端交互约定

- 微信小程序、俄语 H5 和管理后台共享核心业务 API，根据用户身份返回不同权限的数据。
- 游客浏览接口和认证接口分开；私有报价、订单及文件访问必须由后端校验限时令牌、验证码或客户身份。
- 写操作使用幂等标识，避免询价、接受报价或库存锁定因重复点击而重复执行。
- 错误响应采用统一编码，中文和俄文提示由稳定错误码映射，禁止前端依赖后端异常文本判断业务状态。
- 时间在数据库统一保存为带时区时间或 UTC，接口使用 ISO 8601；金额使用十进制定点类型并明确人民币币种。
- API 变更优先保持向后兼容；不兼容变更进入新的接口版本。

详细接口矩阵、响应信封、认证方式、幂等规则和稳定错误码见 [API 契约与错误码](14-api-contract-and-error-codes.md)。机器可读草案为 `api/openapi-v1.yaml`，第一批覆盖公开展示、供应、询价以及后台分配和跟进闭环。

## 6. 数据与安全基线

- PostgreSQL 是业务真实数据源，Redis 不能作为订单和库存的唯一存储。
- 库存锁定、接受报价和订单创建必须在数据库事务中保证一致性，并记录操作人及时间。
- 管理后台实行基于角色的权限控制；成本、毛利、完整证书和数据导出执行额外授权校验。
- 文件采用私有存储桶和限时签名地址，不直接公开永久访问链接。
- 日志不得记录验证码、访问令牌、完整证件信息或其他敏感数据。
- 开发、测试、生产环境隔离；生产数据不得未经脱敏复制到测试环境。

## 7. 代码仓库划分

```text
PotatoLink_doc       需求、业务、产品及技术基线文档（当前仓库）
PotatoLink_frontend  微信小程序、俄语 H5 和管理后台前端（已创建）
PotatoLink_backend   Java 17 后端、迁移脚本、测试和部署文件（已创建）
```

正式仓库地址：

- `https://github.com/azhang111111/PotatoLink_frontend.git`
- `https://github.com/azhang111111/PotatoLink_backend.git`

前端仓库内设置客户端和管理后台两个应用目录。前后端分离的判断依据是构建、部署和 API 边界独立，微信小程序、俄语 H5 和管理后台不再分别建立仓库。

两个代码仓库均为私有仓库，当前由项目方自行开发且不配置外部开发协作者。不得在仓库内保存生产密钥、客户资料、真实报价、合同或未经脱敏的生产数据。新增团队成员时，按工作范围授予最低必要权限并及时回收离岗人员权限。

当前团队规模下采用轻量协作：`main` 始终保存可部署版本，开发变更使用短期 `feature/*` 或 `fix/*` 分支，合并前必须通过构建、测试和静态检查。暂不设置“必须由其他成员审批”的规则；增加开发人员后再启用强制 Pull Request 审批和更严格的受保护分支规则。

## 8. 本地开发环境

项目以 Docker Compose 作为完整本地基础设施方案，两个代码仓库共享一致的服务连接约定：

| 服务 | 本地用途 |
|---|---|
| PostgreSQL | 业务数据库和 Flyway 迁移验证 |
| Redis | 验证码、短期令牌、幂等和锁功能验证 |
| MinIO | 图片、证书、合同、报价单和运输附件测试 |
| 测试邮件服务 | 捕获开发环境邮件，不向真实客户发送 |

后端和前端开发进程可以在宿主机启动，以保留调试和热更新体验；容器通过固定服务名、端口和示例环境变量提供依赖。具体镜像版本在代码仓库初始化时锁定。

当前开发电脑内存有限，暂不安装或启动 Docker 与 Docker Compose。仓库继续提交 `compose.yaml` 作为后续环境配置，但本阶段只运行不依赖容器的后端单元测试、前端类型检查和构建。更换开发环境后，将 Docker/WSL 镜像及数据目录设置到 E 盘，再启动上述服务并补跑 Flyway、数据库及缓存集成测试；这一延期不改变正式技术架构。

开发环境必须提供 `.env.example`，真实 `.env`、访问密钥和本地持久化数据目录加入 `.gitignore`。初始化脚本只生成演示或脱敏数据，不使用生产客户、真实报价、合同和证书。

测试与生产环境不直接照搬本地 Compose 配置，其服务器、托管数据库、对象存储、邮件服务、域名、HTTPS 和备份方案后续单独确认。

## 9. 开发启动前仍需确认

- 测试和生产服务器及云服务商。
- 数据库、Redis、对象存储、邮件服务、域名和证书资源。
- 分支策略、CI/CD、发布审批和生产运维负责人。
- Q-023 中的备份频率、恢复目标、日志周期和告警接收人。
